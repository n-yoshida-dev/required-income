# required-income

家・車・子の大学・老後など、家族のやりたいことを入れると、
**それを全部やるには、年収がいくら要るかを年ごとに出して**、毎日ながめられるようにするアプリです。

<img src="docs/screenshots/home.png" alt="見本の世帯の「ながめる」の画面。やりたいことを全部やるには何年から年収がいくら要るかの文と、この先に要る年収を年ごとに示した階段の形の図" width="320">

（画像は見本の世帯。数字はすべて架空です）

**公開の URL**：<https://n-yoshida-dev.github.io/required-income/>

## だれ向けか

子育て中の家族向けです。スマホで開いて、毎日ながめる使い方を考えて作っています。PC の幅でも同じ画面が使えます。

やりたいことを「期限つきの年収の数字」に直すと、いつまでに年収をいくら上げればよいかが見えます。
要る年収の上がり方が急すぎるときは、目標を外す・時期をずらす・副業を足す、を試して決められます。

## 3 つの画面

| 画面 | できること |
|---|---|
| ながめる | やりたいことを全部やるには、何年から年収がいくら要るかを、文と階段の形の図で見ます。図の段を押すと、その年に何にいくらかかるかと、足りない分を本業・副業・パートナーの収入で埋めるならいくらかが出ます |
| 計画 | 家族・収入・暮らし・目標（家・車・子の費用・大学資金・老後資金・自由な目標）の 4 つのページで入れます。直すたびに保存し、「ながめる」の要る年収がすぐ変わります |
| 見直す | 目標を外す・時期をずらす・金額を変える・副業を足す、を押して試します。「この案にする」を押すまで、今の計画は変わりません |

## 入れた数字はブラウザの中にだけ残る

- 計算はすべてブラウザの中で行います。入れた数字は、使っているブラウザ（localStorage）にだけ保存し、外へは送りません
- そのため、別の端末や別のブラウザでは入れ直しになります。ブラウザのサイトのデータを消すと、入れた計画も消えます

## はじめ方

初めて開くと、見本の世帯（架空の数字）で画面が出ます。見本のあいだは「計画」の欄を直せません。

「自分の数字にする」を押すと、自分の計画が始まり、「計画」の家族のページに移ります。「次へ」を押すと、家族 → 収入 → 暮らし → 目標 の順に進みます。家族・収入・暮らしの欄は見本の値（薄い数字）から始まるので、自分の数字に直してください。目標は、子の費用のカード（子ごとに 1 枚）だけが付いた状態で始まるので、ほかの目標は自分で足していきます。最後の「要る年収を見る」で「ながめる」に戻ります。途中で閉じても、次に「計画」を開くと、まだ済んでいないページから始まります。

見本に戻したいときは、「計画」の目標のページのいちばん下の「見本の世帯に戻す」を 2 回押します。入れた数字はこのブラウザから消え、初めて開いたときと同じ見本の世帯に戻ります。

## 出てくる金額について

- 税金・社会保険・児童手当・保育の無償化・高校の就学支援金・NISA の上限・住宅ローンの金利などの制度の数値は、
  [`frontend/src/data/`](frontend/src/data/) の JSON に、出典（URL）と確かめた日を付けて持っています。コードには直接書いていません
- 出てくる金額は、入れた数字と制度のデータから出した**試算**です。実際の税額や手取りとは違うことがあります。お金の判断についての助言でもありません

## 収録した自治体

国民健康保険料と住民税は、市ごとに料率や上乗せの額が違います。このアプリは次の 7 市の値を持っています。

| 市 | 自治体コード |
|---|---|
| 横浜市 | `14100` |
| 大阪市 | `27100` |
| 札幌市 | `01100` |
| 福岡市 | `40130` |
| 川崎市 | `14130` |
| 神戸市 | `28100` |
| 京都市 | `26100` |

- **選び方**：人口の多い市を上から 8 つ取り、市民税に独自の減税がある名古屋市を除きました。
  人口は総務省統計局「令和2年国勢調査 都道府県・市区町村別の主な結果」（第1面事項、総人口。[e-Stat](https://www.e-stat.go.jp/stat-search/file-download?statInfId=000032143614&fileKind=0)）によります。表は人口の多い順です
- **収録していない市に住んでいるとき**：国民健康保険料は、収録した市のうち人口がいちばん多い市（横浜市）の料率で概算し、画面で概算だと知らせます。
  住民税は標準税率（超過課税なし）で計算します
- **入れていない市独自の値引き**：多子世帯の均等割の減免、独自の控除を見直した後の激変緩和、後期高齢者医療へ移った人がいる世帯の平等割の減額などは計算に入れていません。そのぶん、保険料は高めに出ます
- **会社員の健康保険料**：協会けんぽの都道府県ごとの料率を、住所の都道府県で引きます（本来は勤め先の所在地の料率です）

## 手元で動かす

Node の版は、リポジトリ直下の [`.nvmrc`](.nvmrc)（22 系）に合わせます。

```bash
cd frontend
npm ci
npm run dev
```

表示された URL（ふつうは http://localhost:5173/）をブラウザで開きます。

### 検査とテスト

`frontend/` で回します。上の 5 つは CI（[`.github/workflows/ci.yml`](.github/workflows/ci.yml)）と同じ検査です。

| コマンド | 内容 |
|---|---|
| `npm run format:check` | 整形の崩れがないか（直すときは `npm run format`） |
| `npm run lint` | ESLint |
| `npm run typecheck` | 型の検査 |
| `npm test` | 単体テスト（Vitest） |
| `npm run build` | 公開する形にビルドする（`frontend/dist/`） |
| `npm run e2e` | 通しテスト（Playwright）。ビルドした物を出し、スマホの幅で主な操作 1 本を通す。初回は `npx playwright install chromium` |

### 公開の仕組み

main に入ると、[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) が `frontend/` をビルドして GitHub Pages に出します。
画面の行き先は `#/plan` のようなハッシュで、ビルドした物は相対パスで読み合うので、置く場所（サブパス）を問わず開けます。
Private のリポジトリでは、このワークフローは動きません（skip になります）。

## 使っている物

React + TypeScript（strict）+ Vite、React Router（画面の切り替え）、Zod（保存の形の確かめ）、Vitest（単体テスト）、Playwright（通しテスト）。

## フォルダの作り

```
frontend/
  src/
    domain/     計算（React やブラウザに触れない関数だけ。単体テストの対象）
    data/       制度の数値、アプリの既定値、見本の世帯（JSON）
    features/   画面（home＝ながめる、plan＝計画、review＝見直す、shared＝共通の部品）
    app/        画面の切り替え、開く計画を決める所、見た目の値（app.css）
    storage/    ブラウザへの保存
  tests/        単体テスト
  e2e/          通しテスト
docs/
  screenshots/  README の画像
```

開発には Claude Code を使っています。
